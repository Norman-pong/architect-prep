## 1. 背景与目标

### 1.1 业务背景

「系统架构设计师」(软考高级) 考试覆盖 20 章知识点，三科考试（综合知识/案例分析/论文）。备考需要系统化的知识学习 + 大量真题练习。现有 GitHub 题库资源分散在多个仓库，格式不一（PDF/Markdown/JSON），缺少统一的学习和刷题工具。

### 1.2 产品目标

构建一个可自托管的 Web 平台，将教材知识体系与 GitHub 开源题库整合，提供知识浏览 + 刷题 + 错题管理的一体化备考体验。

### 1.3 成功指标

- 知识体系 20 章全覆盖
- 题库 ≥500 题（真题 + 模拟）
- Docker Compose 一键部署

## 2. 用户与场景

### 2.1 目标用户

| 用户角色 | 描述 | 核心诉求 |
| -------- | ------ | -------- |
| 备考考生 | 工程师，准备系统架构设计师考试 | 知识学习 + 真题练习 + 错题复习 |

### 2.2 使用场景

1. 知识学习：按章节浏览知识点，搜索关键概念
2. 刷题练习：章节练习/随机抽题，即时判分+解析
3. 错题管理：自动收集错题，针对性复习

### 3.2 详细功能描述

#### 3.2.1 邮箱验证码登录

**功能说明**：用户输入邮箱，系统发送 6 位验证码，验证后创建/登录账户。

**处理逻辑**：
1. 用户输入邮箱 → POST /auth/send-code
2. 服务端生成 6 位随机码，内存存储 60s TTL
3. SMTP 发送验证码邮件
4. 用户输入验证码 → POST /auth/verify-login
5. 校验验证码 → 查询/创建用户 → 签发 JWT (7 天)

#### 3.2.2 知识体系浏览

**功能说明**：按教材 20 章结构展示知识体系，支持层级浏览和搜索。

**数据来源**：教材章节 + 知识点内容结构化入库。

#### 3.2.3 刷题练习

**功能说明**：按章节选择题目，逐题作答，提交后判分并展示解析。

**判分逻辑**：选择题 answer_keys 为数组（如 ["A"] 或 ["A","C","D"]），用集合比对判分。

## 4. 非功能需求

### 4.1 性能要求

- 前端 SPA 静态部署，首屏 <2s
- API 响应 <200ms
- SQLite 嵌入式，单机部署

### 4.2 安全要求

- 认证：邮箱验证码 + JWT
- 验证码 60s TTL，一次性使用
- JWT 7 天有效期，Bearer token

## 9. 风险与约束

### 9.1 已知风险

| 风险 | 影响 | 概率 | 应对 |
| -------- | ------ | ------ | ------ |
| Markdown 题库格式不统一 | 中 | 高 | 按仓库编写不同解析器 |
| 知识点内容量大 | 中 | 中 | 分批导入，优先高频考点 |

### 9.2 约束条件

- 前端工具链一律用 vp
- 后端用 SQLite 不用 PostgreSQL
- 基于 @base-ui/react 做 UI 设计
